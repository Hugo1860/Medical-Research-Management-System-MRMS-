# PDF 计划书导入回归

测试直接调用生产 `ProposalPdfParser` 和 `ProposalImportStore`。解析测试使用内存生成的真实压缩 PDF；数据库测试从已迁移的正式表定义创建独立 schema 和合成数据，结束后清理该 schema，不调用外部服务，也不使用医院业务数据。

```bash
PROPOSAL_IMPORT_TEST_CONNECTION='<隔离 PostgreSQL 连接串>' \
PROPOSAL_IMPORT_TEST_ALLOW_FIXTURES=YES \
dotnet run --project tests/ProposalImportRegression
```

缺少连接或显式 fixture 开关时，数据库测试不会运行并以退出码 2 结束；不能将此结果记作完整通过。连接串不得提交或打印。

覆盖：压缩 PDF 文字层、无文字层及伪 PDF、金额单位换算、缺项无默认值；上传数量、单份 20 MiB 与总计 100 MiB 边界；同批重复文件与计数幂等、人工复核门禁、同名/停用负责人、单批失败原子性、并发确认防重复、真实日期/金额落库、跨批批准号查重及忽略损坏原件；旧路径同哈希重传、已导入及关闭批次原件补传、不一致文件拒绝及核对字段保持。

上传每次最多 10 份 PDF，单份不超过 20 MiB，文件合计不超过 100 MiB。接口和 Nginx 请求体上限为 102 MiB，额外空间仅供 multipart 封装使用。

历史原件恢复：科研管理员在导入明细选择“补传原件”，上传首次上传时的同一份 PDF；后端校验 SHA-256 与记录完全相同，再保存至受控 `App_Data/ProposalImports` 目录。已导入或关闭的批次同样可恢复原件，保持核对信息、项目关联和批次状态。未完成批次也可通过普通上传恢复同哈希文件。没有原始文件或哈希不一致时不能替换，应从可信备份找回原件。此入口不提供旧静态目录的匿名访问；旧 `wwwroot/upload/纵向项目导入` 的历史副本需由运维在受控恢复及备份核验后归档并撤销公开静态访问，不应为兼容性放开目录下载。

这是隔离环境回归，不替代真实多角色权限、医院项目材料及正式上线验收。
