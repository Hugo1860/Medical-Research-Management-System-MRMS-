# 外部系统集成契约

当前系统将外部集成分为 HR、财务、采购、伦理、合同、人才库、生物样本库和论文采集八类。每个系统只登记系统代码、基础地址、认证方式和认证引用；认证引用对应部署环境中的密钥名称，数据库不保存 token、密码或私钥。

每一类在启用 worker 前必须保留且仅保留一个“启用且配置完整”的适配器；可以登记停用候选，但重复启用会阻断 worker 启动。`GET /Operations/获取外部系统配置检查` 会返回八类逐项结果、启用数量、密钥注入状态和参数问题。

## 同步任务

业务模块通过 `POST /Operations/创建外部同步任务` 写入统一队列，任务必须包含：

- `外部系统编号`：目标系统注册编号；
- `业务类型`：例如 `人员变更`、`项目立项`、`项目预算`、`伦理结果`、`经费报销`；
- `方向`：`推送` 或 `拉取`；
- `业务主键`：业务记录的稳定标识；
- `幂等键`：同一业务事件的全局唯一键；
- `请求负载`：经过字段白名单处理的 JSON 数据。

重复提交相同幂等键会返回原任务，不会产生第二条队列记录。任务状态包括 `待处理`、`处理中`、`成功`、`失败` 和 `已取消`，并保留尝试次数、下次重试时间、请求 ID、外部响应摘要和最后错误。

worker 使用 `ExternalSync:LeaseTimeoutSeconds`（默认 900 秒）作为处理租约。进程在供应商响应落库前退出时，下一轮会自动回收过期的 `处理中` 任务；达到最大尝试次数的任务转为 `失败`，可通过 `GET /Operations/获取外部同步失败告警` 只读查看。

## 接口约束

外部适配器应使用登记的基础地址，按系统配置的超时秒数和最大重试次数执行；重试只允许对网络超时、连接失败和 5xx 响应进行，4xx 业务校验错误直接进入失败状态。每次请求必须带 `X-Request-ID` 和幂等键，外部系统返回的业务编号写入响应摘要或业务映射表。

启用 `ExternalSync` worker 后，任务以 POST JSON 发送到登记的基础地址，正文包含 `businessType`、`direction`、`businessKey`、`idempotencyKey`、`requestId` 和原始 `payload`；供应商适配器负责按自身协议转换为真实 HR、财务、采购、伦理、合同、人才库、生物样本库或论文采集请求。worker 默认关闭，未配置真实地址和认证引用时不会发起外部请求。

P2 版本将供应商响应视为**受控回执**：只有 HTTP 2xx 才能把任务标记为成功，响应摘要仅保留业务编号、受理状态和有限诊断；访问令牌、密码、Cookie、`Authorization`、API key 以及其他敏感响应字段会在写入队列和日志前脱敏为 `[REDACTED]`。回执必须能够通过 `requestId`、幂等键和供应商业务编号关联到本地任务，不能只凭“接口返回 200”补写本地业务状态。未完成八类真实联调前必须保持 `ExternalSync__Enabled=false`。

重试分类固定为：网络错误、请求超时、408、429 和 5xx 可按退避策略重试；其他 4xx 进入终态失败并保留可审阅的错误摘要。429 的 `Retry-After` 最多遵循 1 小时；进程崩溃造成的过期租约由 worker 回收。人工重试只能作用于 `失败` 或 `已取消` 任务，保留原幂等键并产生新的请求 ID。

## 安全边界

系统注册和任务运维接口仅对系统管理员、科研管理员开放。生产环境的认证密钥通过容器 Secret、环境变量或密钥管理服务提供，禁止写入 PostgreSQL、日志和错误响应。真正接入八类医院系统前，需要分别配置地址、认证引用、字段白名单、回调签名、脱敏规则和联调账号，再进行生产级验收。

外部回调（如财务付款回写、伦理批文同步、论文采集结果、HR 离岗通知）必须校验签名、时间窗和幂等键；未通过签名或重复回调不得更新业务表。当前仓库只提供统一队列与回执落库边界，真实供应商回调地址、签名算法、证书和字段协议仍需在联调登记表中逐项确认。`verify-external-p2-contract.sh` 只检查这些边界是否固化在代码和文档中，不伪造回执，也不调用供应商。

P2 真实联调至少保留以下证据：每类系统各一条成功的供应商**真实回执**、同一幂等键的**幂等重放**结果、失败任务的请求 ID/尝试次数/最终错误，以及回调签名校验记录。出站请求的 `X-Request-ID` 和 `Idempotency-Key` 必须原样记录在验收报告中，并与本地队列任务和供应商业务编号关联保存；只看到本地“预检通过”或 HTTP 连接成功，不能标记为已联通。

## P2 八类系统回归矩阵

| 系统 | 最小回归事件 | 必须核对的本地结果 |
|---|---|---|
| HR | 在职、离岗、部门变更 | 稳定外部人员映射、人员状态、代理授权回收、真实回执 |
| 财务 | 到账、付款、冲销 | 业务编号/外部流水号幂等、付款回写状态、失败重试 |
| 采购 | 申请、订单、验收 | 采购订单稳定编号关联项目/发票/付款、重复事件不重复入账 |
| 伦理 | 批文批准、过期、撤回 | 伦理同步记录、有效期、附件凭证、签名回调 |
| 合同 | 签订、变更、付款节点、终止 | 原合同编号及版本、付款节点、档案回执 |
| 人才库 | 画像更新、导师关系、合作意愿 | 业务必要字段白名单、敏感字段不出日志、幂等更新 |
| 生物样本库 | 样本入库、领取/释放、状态变更 | 仅同步样本编码/数量、关联项目与伦理编号、无受试者身份信息 |
| 论文采集 | 新论文、重复 DOI/PMID、更正 | 外部论文编号幂等、待认领状态、已认领成果不被覆盖 |

## 连接测试

运行管理角色可调用 `POST /Operations/测试外部系统连接` 对已登记系统执行一次轻量 GET 测试。接口使用登记的认证方式和部署环境密钥引用，返回 HTTP 状态码、耗时和诊断说明，不会自动启用外部系统。

治理中心提供受控的队列操作：可按幂等键手工创建同步任务，并对失败或待处理任务执行重试、取消；这些操作仍受运行管理角色和服务端幂等约束，不能绕过外部系统注册或认证配置。

## 经费与 HRP 专项预检

`GET /Operations/获取经费适配器契约检查` 是只读门禁，检查 HR、财务、采购三类适配器是否各有唯一启用且完整的配置，并核对 HRP 四类中间表、发票查重/OCR 状态、预算调整版本、年度结算和付款台账。它还会报告采购订单稳定编号是否已落到发票、报销或付款记录。

历史运行库中的 `sp_hrp中间库双向协同` 过程曾包含示例付款写入逻辑。迁移 085 将该过程替换为安全的 `push_only` 实现：仅把纵向项目和预算写入待同步队列，不读取或写入示例付款流水，并拒绝 `push_and_replay`/`replay` 及其他动作。在迁移 085、086、087 尚未应用的运行库中，真实 HRP 回放仍保持阻断；`POST /Expense/Hrp中间库双向协同` 同样只允许 `push_only`，避免按钮操作生成伪造付款。该接口和同步状态查询均要求财务管理角色或项目范围授权。

发票接口当前只实现人工录入、号码/供应商金额查重和人工复核。OCR 未配置真实服务时，`OCR状态=人工录入` 不得当作已识别；预算调整、付款回写和年度封账只能证明本地数据库约束，不能替代 HRP/财务供应商回写验收。部署前可执行 `./deploy/verify-finance-adapter-contract.sh --strict`，该脚本只读访问 PostgreSQL 和容器配置，不发起外部请求，也不生成验收数据。
