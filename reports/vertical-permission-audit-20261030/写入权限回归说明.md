# 纵向项目写入权限回归

在独立、无外网的 PostgreSQL 18 测试数据库中，以合成部门、人员、流程、步骤、项目及子记录调用实际控制器和工作流业务方法。测试结束清理测试数据。源码副本中的控制器与工作流业务文件与执行时工作区文件逐字节一致。

结果：**57 项断言通过**，完整输出见同目录《写入权限回归输出.txt》。

覆盖：

- 申报、立项、中检、变更、结题五类实体：合法绑定、伪造其他实体、错误流程模板、无权操作人员、已结束步骤；三个生命周期阶段还覆盖伪造父项目。
- 五类控制器的合法暂存与完成实际写入并读取数据库确认；交叉项目请求被拒绝且另一实体保持原值。
- 新增申报、三类立项、变更拒绝已有编号；申报转立项拒绝无权访问的来源；变更应用拒绝其他变更编号且步骤未被完成。

边界：使用合成身份直接调用控制器，并非真实浏览器、医院账户或外部系统验收；未验证合法申报转立项、新增项目完整业务闭环或合法变更应用的业务结果。测试要求迁移至 120 的隔离数据库，不能用于生产数据库。

复现时以 `DB_CONTAINER` 指向已准备好的独立测试数据库容器：

```sh
build_dir=$(mktemp -d /tmp/vertical-write-test.XXXXXX)
mkdir -p "$build_dir/ScientificResearch/ScientificResearch" "$build_dir/tests/VerticalWriteScopeRegression" "$build_dir/nuget"
rsync -a --exclude bin --exclude obj --exclude wwwroot ScientificResearch/ScientificResearch/ "$build_dir/ScientificResearch/ScientificResearch/"
cp tests/VerticalWriteScopeRegression/* "$build_dir/tests/VerticalWriteScopeRegression/"
docker run --rm -v "$build_dir:/src" -v "$PWD/deploy/nuget-local:/nuget:ro" -v "$build_dir/nuget:/root/.nuget/packages" -w /src scientificresearch:local-sdk sh -c 'dotnet restore tests/VerticalWriteScopeRegression/VerticalWriteScopeRegression.csproj -p:UseAppHost=false -p:SelfContained=false --source /nuget --source https://api.nuget.org/v3/index.json --disable-parallel --verbosity quiet && dotnet build tests/VerticalWriteScopeRegression/VerticalWriteScopeRegression.csproj -c Release --no-restore --verbosity quiet'
docker run --rm --ulimit core=0 --network "container:$DB_CONTAINER" -v "$build_dir:/src" -w /src -e 'VERTICAL_WRITE_TEST_CONNECTION=Host=127.0.0.1;Port=5432;Database=ScientificResearch_Model;Username=postgres' -e VERTICAL_WRITE_TEST_ALLOW_FIXTURES=YES scientificresearch:local-sdk dotnet tests/VerticalWriteScopeRegression/bin/Release/net10.0/VerticalWriteScopeRegression.dll
```
