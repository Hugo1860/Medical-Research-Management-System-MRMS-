# 纵向项目权限范围核查与验证

## 修改范围

- 申报六个列表入口和中检、变更、结题列表在数据库统计总数及分页之前限制人员可见范围；保留原筛选条件。项目管理员、负责人、参与人、流程发起人及现有父流程授权人员按既有规则访问；阶段专属待处理人只获得对应阶段记录的访问权。
- 生命周期详情核对中检、变更、结题记录与立项的归属，结题所引用的中检记录也必须属于同一立项。
- 申报、立项、中检、变更、结题完善以及变更应用在流程事务内锁定并核对步骤、流程模板、实际记录及其父立项；新增申报、立项、变更拒绝已有编号，申报转立项先检查来源访问权。

## 测试证据

- 在迁移至 120 的独立 PostgreSQL 18 数据库中，使用合成角色和数据直接调用实际控制器，列表与详情 **148 项断言通过**，见 [列表详情输出](list-details-pass.txt)。另外，仅在临时源码副本中人为移除列表权限条件，负向对照按预期失败，见 [负向对照](list-scope-negative.txt)；这不是历史版本红测。
- 五阶段控制器与工作流写入 **57 项断言通过**，包括真实暂存、完成及数据库持久化，跨项目写入拒绝和目标未变；见 [写入权限回归说明](写入权限回归说明.md) 与 [输出](写入权限回归输出.txt)。
- 测试代码分别位于 `tests/VerticalLifecycleScopeRegression` 和 `tests/VerticalWriteScopeRegression`。`git diff --check` 通过。测试夹具和临时编译目录已清理。

## 未覆盖与既有边界

- 这是合成身份的直接控制器与数据库测试，不代表 HTTP 身份认证、医院真实账号、浏览器操作及真实外部系统验收；本次修改尚未部署云端。
- 合法申报转立项、新增项目完整业务闭环及合法变更应用的业务结果未在此次写入回归中验证。申报转立项创建流程与来源标记仍分属两次事务，失败或并发时可能状态不一致。
- 申报和父立项沿用既有 `CanAccessProjectAsync` 阅读规则：当前步骤的角色成员即使并非指定人，也可能获得阅读权限；该规则不同于操作权限的指定人优先。阶段子流程新增的访问权限使用实际步骤操作规则。角色是否应保留上述父流程阅读权需业务确认，不能将两者混同。
