1. 管理员真实登录独立 Keycloak，并从页面创建合成测试批次 `UAT-BATCH-26a8e6cfd677`。

## 权限及异常边界（修复前候选）

- 未登录查询批次、下载原件：401。两位“项目负责人”角色查询或创建导入批次：403。
- 未复核批次：两位负责人下载原件均为 403，管理员确认导入返回 400；无新增立项。
- 已导入原件：管理员和负责人下载 200、无关人员 403；管理员页面下载及负责人 API 下载的内容哈希均与合成原件一致。负责人此前没有界面下载入口，API 200 不能视为页面下载通过。
- 主批次重复确认返回 200、新增 0 项。另建合成重复批次时批准号查重失败，确认返回 400，主项目未重复创建。
- 初始无业务角色的两人先进行了相同阻断探针；之后为两人补配项目负责人角色，并重新执行上述关键权限检查。

1. **立项列表越权：** 为无关人员建立第二个合成项目后，管理员、负责人 A 和负责人 B 的列表均返回两个项目，尽管双方读取对方详情均为 403。已修改立项三类分页的服务端筛选并新增 `立项文号` 字段，保持管理员范围及原流程 `项目编号` 语义；新增真实控制器与隔离数据库回归。**修复后的后端尚未重新编译或执行回归，也尚未重新部署真实账号复验。**
2. **页面展示：** 生命周期列表未显示正确项目名称和批准号；负责人工作台统计接口返回 403 时将未知值显示为 0；负责人没有可见的计划书原件下载入口。已有前端修复及 10 项组件测试、TypeScript 检查，但尚未与修复后的后端一起构建发布并浏览器复验。
3. **其他项目列表风险：** 申报、中检、变更和结题分页静态检查也发现类似缺少范围过滤的风险，尚未完成真实用户实测或修复，不得据此宣称全系统项目权限通过。
4. **统计口径：** 全院统计使用流程视图，可能遗漏无流程导入项目或重复计数同一项目；本轮未将其当作准确的项目总数。
5. **界面提示：** 登录页显示了预置示例账号文案，即使隔离人员库只有本次三位测试人员；不应把这些文案作为账号真实存在的证据。

## 中断原因与恢复

完成上述旧候选的业务及权限探针后，宿主可用磁盘下降至约 600 MiB，Docker 无响应，隔离应用健康检查无法连接。已停止构建；未重启 Docker，也未清理其他项目的镜像、容器或数据。测试 PDF 原件已在本次私有临时目录备份并核对哈希；本次临时账号与服务的凭据文件已删除。数据库使用临时存储，恢复运行后必须重新确认数据是否仍存在，不能假定完整保留。Docker 恢复后需清理或重建带 scientificresearch.isolated-uat=true 标签的本次测试资源。

磁盘与 Docker 恢复后，应先验证现有运行资源及备份，然后重建并校验修复候选；使用专属隔离环境重放控制器回归及真实 Keycloak 角色测试，复验列表范围、页面项目名称/文号、负责人页面下载与哈希、刷新持久化和异常阻断；最后单独检查申报、中检、变更、结题列表的数据范围。未经这些步骤不能把修复或验收标记为通过。本次没有发布或变更生产环境。
